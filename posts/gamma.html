Gamma: compile the vocabulary, resolve the value

A source-level tour of Gamma — a SwiftUI design-system foundation that turns a JSON token contract into typed aliases, then resolves their values from the current environment and view scope.

Part 1A design system can drift without changing its source file

A design system usually begins with a tidy promise: define a palette, a type scale, and a spacing scale once, then use them everywhere. The drift begins in the translation. A JSON key becomes a handwritten Swift constant; a component accepts any CGFloat; dark appearance is a switch in one view; an Arabic font is selected in another; a campaign duplicates half the palette to change three values.

The source of truth may still be pristine. The application has quietly created several more sources of truth in the code that interprets it. Renaming spacing/medium can leave an old string alive in one feature. Passing a corner-radius token where a component expects padding still type-checks because both happen to be numbers. A remotely delivered theme may decode successfully even though it no longer contains a token the binary was built to use.

Gamma draws a line between two things that design-system tooling often fuses: the token vocabulary is a compile-time contract; the token values and mode policy remain runtime data. A build plugin reads the same theme file the app bundles, generates typed Swift aliases from its keys, and fails the build when several theme variants disagree about that alias surface. At runtime, a resolver maps the current SwiftUI environment to the mode names in the active theme.

The central idea. Gamma solves drift between theme data and view code by compiling stable token identity into Swift while resolving replaceable values only where a view has an environment and a scope.

That division is the useful design decision. It makes spelling and semantic groups visible to the compiler without freezing a brand color, a responsive spacing value, a script-specific font, or a server-provided theme into the binary.

Part 2Compile the vocabulary, keep the values replaceable

A Gamma theme is ordinary JSON with one identity, defaults, and token families. Each token has a complete key, a semantic group, and one or more named modes. The mode names belong to the design system. The sample theme uses day and night for colors, latin and arabic for fonts, and compact and regular for units.

{
  "id": "gamma-sample",
  "colors": {
    "brand/accent": {
      "name": "Accent",
      "group": "brand",
      "modes": {
        "day":   { "hex": "#5B4CF0", "alpha": 1 },
        "night": { "hex": "#9A91FF", "alpha": 1 }
      }
    }
  },
  "units": {
    "spacing/medium": {
      "name": "Medium",
      "group": "spacing",
      "modes": { "compact": 16, "regular": 24 }
    }
  }
}

Attach GammaBuildPlugin to the consuming target and keep the *.theme.json file in that target. The plugin discovers theme files recursively, validates their alias contracts, and emits a bundled resource handle plus declarations such as ThemeResource.app, .brandAccent, and .spacingMedium. It uses the JSON key as the alias raw value; the generated member is a Swift spelling for that key, not a copied design value.

The generated resource and the generated alias surface come from the same build input. A bundled resource is decoded once per resource-and-bundle pair and reuses that identity during later SwiftUI evaluations. A downloaded RawTheme enters the same runtime path, but it must preserve the alias keys compiled into the app. Gamma does not pretend that a server can add a brand-new Swift member to an already shipped binary.

Generation is not bundling. In a Swift package target, the theme still needs a resource declaration. The plugin creates Swift declarations; target resources make the JSON available when the app runs.

Part 3Use one alias in two kinds of contract

Colors, fonts, and units each form a family. A token’s group adds a narrower semantic scope inside that family. For spacing/medium, Gamma generates the same accessor on a family alias and on Theme.Units.SpacingAlias. Those two types answer different design questions.

Theme.Alias<Theme.Units>Composition surface. A property or switch may choose spacing, radius, size, or any other unit group, because every case still resolves to a unit.
Theme.Units.SpacingAliasRestriction surface. A component parameter can accept spacing tokens while rejecting radius and size tokens before the app runs.

This is more than generated autocomplete. Consider a card whose measurements all resolve to CGFloat. A loosely typed API cannot distinguish correct values from plausible mistakes. A Gamma component can carry the design-system distinction in its initializer:

struct TokenCard<Content: View>: View {
  let background: Theme.Colors.SurfaceAlias
  let foreground: Theme.Colors.TextAlias
  let padding: Theme.Units.SpacingAlias
  let cornerRadius: Theme.Units.RadiusAlias
  @ViewBuilder let content: Content

  @ThemeReader private var theme

  var body: some View {
    content
      .foregroundStyle(theme.color(foreground))
      .padding(theme.unit(padding))
      .background(theme.color(background))
      .clipShape(
        RoundedRectangle(cornerRadius: theme.unit(cornerRadius))
      )
  }
}

.spacingMedium and .radiusCard both work with the family-wide theme.unit(...) resolver, yet exchanging them in this initializer is a compile-time error. The group restricts the component boundary; the family determines the output type and resolution machinery.

The broader alias remains important. Application logic may need to choose across groups while preserving one family contract:

var measurement: Theme.Alias<Theme.Units> {
  switch role {
  case .contentInset: .spacingMedium
  case .cardCornerRadius: .radiusCard
  }
}

Empty groups do not produce an artificial scope. A slash-free token such as body stays family-only. Grouped keys, meanwhile, must contain exactly two non-empty components and begin with their declared group. Code generation rejects collisions after Swift-name normalization rather than silently choosing one declaration.

Part 4Let the environment choose the concrete value

A view never asks the JSON directly for day, arabic, or regular. It asks for .brandAccent, .typographyBody, or .spacingMedium. A ThemeModeResolving value owns the policy that translates the current environment into the theme’s vocabulary.

struct AppThemeModeResolver: ThemeModeResolving {
  func modes(for context: ThemeModeContext) -> ThemeModes {
    ThemeModes(
      colors: .init(light: "day", dark: "night"),
      fonts: context.layoutDirection == .rightToLeft
        ? .init(primary: "arabic", cascades: ["latin"])
        : .init(primary: "latin", cascades: ["arabic"]),
      units: context.horizontalSizeClass == .regular
        ? "regular"
        : "compact"
    )
  }
}

@ThemeReader participates in SwiftUI’s dynamic-property lifecycle. During an update, it captures one coherent snapshot of the active theme, resolver, color scheme, layout direction, horizontal size class, and override identity. Every token read during that body evaluation uses the same resolver result. Dynamic Type remains part of font application because the concrete font must be rebuilt for the requested size.

Use this model to answer one question: what does the same component contract resolve to in this subtree? Change appearance, width, and scope. The component keeps reading the same aliases; only the selected modes and active token values change. The values come directly from Gamma’s SampleApp theme and campaign override.

    Colors receive a pair of selected modes and become a dynamic platform color, so one returned value follows light and dark appearance. Units resolve one selected mode. Fonts resolve one primary mode plus ordered cascade modes, then Gamma’s font modifier applies scaling, line spacing, letter spacing, and text case. A custom family can define its own mode payload and add a typed assignment to the same ThemeModes result.

    Resolved caches include the decoded theme identity, composed override identity, resolver identity, and relevant environment context. This is why a compact value cannot leak into a regular-width subtree, and why two identical aliases under different overrides do not accidentally share a concrete result.

    Part 5Replace a subtree without inventing a second theme

    A campaign card, partner flow, or accessibility treatment may need a local visual voice. Copying the entire theme creates another document that can drift. Gamma instead transforms the active RawTheme for one view subtree. Siblings and ancestors continue to read the base theme.

    let campaign = ThemeOverrides(tokens: [
  try ThemeTokenOverride(
    Theme.Colors.BrandAlias.brandAccent,
    modes: [
      "day": .init(hex: "#D63F77", alpha: 1),
      "night": .init(hex: "#FF82AD", alpha: 1)
    ]
  ),
  try ThemeTokenOverride(
    Theme.Units.RadiusAlias.radiusCard,
    modes: ["compact": 8, "regular": 12]
  )
])

WithThemeOverrides(overrides: campaign) {
  CampaignCard()
}

    An override replaces the complete mode dictionary for one existing token. It does not merge individual modes, introduce a new family, or invent an alias that generated Swift does not know. That rule makes a remotely supplied treatment self-contained: an old base value cannot unexpectedly fill a mode the override forgot to provide.

    Nested overrides are ordered transformations. Their identity combines with the parent identity, and tests verify that reversing the nesting order produces a different cache scope. The transformed theme is validated against the active resolver, including registered extension families, before descendants resolve it.

    Overrides carry values, not infrastructure. If an overridden font names a custom face, the app must make that file available at the root theme installation. WithThemeOverrides does not download or register font files.

    Part 6Remote themes, custom families, and honest failure

    The alias pattern is not limited to color, typography, and units. A consumer-defined ThemeExtension supplies a codable mode payload, and Gamma generates family and group aliases for its JSON root. The SampleApp defines a gradient mode as an ordered list of color-token keys. Its app-owned ThemeProxy.gradient(...) helper resolves the selected gradient payload, then resolves each stop through Gamma’s color family.

    extension ThemeProxy {
  func gradient<Scope: ThemeAliasScope>(
    _ alias: Theme.Alias<Scope>
  ) -> LinearGradient where Scope.Family == Theme.Gradients {
    guard let mode = resolve(alias) else {
      return LinearGradient(colors: [.clear], startPoint: .top, endPoint: .bottom)
    }

    return LinearGradient(
      colors: mode.stops.map {
        color(Theme.Alias<Theme.Colors>(rawValue: $0))
      },
      startPoint: .topLeading,
      endPoint: .bottomTrailing
    )
  }
}

    The library owns decoding, validation, supplied local-font registration, environment activation, and resolution. The application owns transport, storage, rollout policy, and loading UI for server themes. Publishing a decoded theme together with its completed local font URLs avoids a state where the new values render before their files exist.

    Gamma checks failure at the closest useful boundary. Malformed built-in schema fails decoding. Alias collisions and disagreement among bundled theme variants fail generation. Resolver-selected modes and registered custom families are validated during installation and when resolution context changes. Missing compiled aliases that are not part of the defaults surface when a view actually reads them.

    Debug builds assert on invalid configuration after emitting a consolidated diagnostic. Release resolution remains total for built-in families: colors fall back to black in light appearance and white in dark, fonts fall back to a system font, and units fall back to zero. A custom-family resolver returns nil so the app-owned conversion method can supply a domain fallback.

    Part 7API reference, limits, and verdict

    .theme(...) and @ThemeReader

    Install a generated ThemeResource or decoded RawTheme at a view root, optionally with a custom resolver, local font URLs, and extension registrations. Read the active snapshot through @ThemeReader, then call color, font, unit, or an app-owned custom-family helper.

    Theme.Alias, families, and generated groups

    A family alias composes any token that resolves to the same output kind. A generated group alias narrows a component parameter to one semantic group. Aliases are RawRepresentable, Codable, Hashable, and Sendable; their encoded form is the complete token-key string.

    ThemeModeResolving and ThemeModes

    A resolver receives color scheme, layout direction, and optional horizontal size class. It must provide color, font, and unit selections, plus typed assignments for registered custom families. Stateful policy exposes cacheIdentity so concrete token caches follow policy changes.

    ThemeOverrides and ThemeExtension

    Overrides replace complete mode dictionaries for existing tokens inside one subtree. Extensions add app-owned token payloads to Gamma’s generation and runtime pipeline; the app supplies a proxy conversion method and fallback.

    Gamma shines when…Watch for…
    A product needs runtime theme values without returning to handwritten string keys in SwiftUI.A server theme cannot change the alias surface of an already compiled binary.
    Components should distinguish semantic token groups even when their concrete Swift types match.The team still has to design a coherent token vocabulary and group taxonomy.
    Appearance, writing direction, width, and local campaigns should change values without changing component code.Resolver policy must stay deterministic, cheap, and represented in cache identity when stateful.
    Custom token families should share validation, modes, overrides, and environment activation.The app owns custom payload rendering plus remote transport, persistence, and rollout UX.

    Gamma is a good fit when a design system needs both a stable language and replaceable expression. Its generated aliases keep views and component contracts attached to the vocabulary the binary understands; its resolver and subtree overrides keep concrete values responsive to environment, brand, and local context. The tradeoff is deliberate: teams must treat token identity as an API, not as a bag of remote strings. Once they do, design changes can move at runtime without asking every view to reinterpret the system for itself.
